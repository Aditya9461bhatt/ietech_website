- [ ] **No Firestore security rules on master — admin authz is client-side only.** `firestore.rules` doesn't exist on master; `AdminDashboard.tsx:71-77` and `AdminCMS.tsx:83-89` gate on a hardcoded, duplicated `ALLOWED_ADMIN_EMAILS` array shipped in the public bundle. - [ ] **Google sign-in "leads" are silently lost everywhere.** `Hero.tsx:11-24`, `ContactModal.tsx:61-79`, `UseCaseManufacturing.tsx:17-30`, `UseCaseRestaurant.tsx:17-30`: after `signInWithPopup` the UI claims "Inquiry received / We've got your details" but **nothing is written to Firestore** — only the email-form path in `ContactModal.tsx:44-51` persists a lead. - [ ] **ContactModal is unreachable dead UI.** `App.tsx:33-37`: `setContactOpen(true)` is never called anywhere — every "CONTACT US" opens a Gmail compose tab instead. The entire in-site contact-capture flow never runs. Wire it up or delete it.
- [ ] **"Inquiry received" is driven by global auth state.** Any visitor who ever signed in sees the success chip forever on Hero and both use-case pages and *loses the "Request a Demo" button* (`UseCase*.tsx:77`, `Hero.tsx:79-122`). Track per-page submission state, not `user`.
- [ ] **CMS literal `\n` bug corrupts published content.** `AdminCMS.tsx:72, 278-287`: new-doc templates and all toolbar buttons insert the two characters `\n` (backslash-n) instead of newlines — toolbar headings/lists never render as markdown and the junk publishes live. Five occurrences.
- [ ] **CMS slug collision = silent data loss.** `AdminCMS.tsx:139-176`: `setDoc` on a hand-typed slug with no existence check, no format validation (a `/` throws, spaces/uppercase break URLs). Publishing with an existing slug silently overwrites that document.
- [ ] **Site is invisible to search engines and social scrapers.** 100% client-rendered SPA + hash-based routing (`#/blogs`, `#/project/...`) means crawlers see one near-empty page; no OG/Twitter tags, no canonical, no `robots.txt`, no `sitemap.xml`. `[feat✓]` — feat converts to path routing (react-router `Routes`), per-page `<head>` via React 19 native metadata (`Seo.tsx`), Puppeteer prerender of every route incl. Firestore slugs (`scripts/prerender.mjs`), generated sitemap, robots.txt, canonical, OG tags, noindex on admin.

## Stash vs `feat/ssg-seo-security` — comparison & verdict

Both attack the same problems (real URLs, per-page SEO, Firestore security, deploy hardening). The feat branch is the same ideas done better, and it's based on newer code.

| Concern | Stash (local WIP, based on old master `9efee713`) | feat/ssg-seo-security | Winner |
|---|---|---|---|
| Routing | react-router-dom + hand-rolled router.tsx | react-router-dom `Routes` + lazy chunks + NotFound + ScrollToTop | feat |
| SEO head | react-helmet-async `SEOHead` | React 19 native `<title>/<meta>` hoisting (`Seo.tsx`) — explicitly avoids helmet's duplicate-tag bug under React 19 | feat |
| Crawlers | Cloudflare edge-router worker | Puppeteer post-build prerender of all routes incl. Firestore slugs + generated sitemap | feat |
| Firestore rules | `contacts` lead-shape only — collection name doesn't even match master's `contact_submissions` | Full rules: admin allowlist, public validated lead create, deny-all | feat |
| Security headers | `public/_headers` (Pages-style, wrong for nginx) | `nginx/security-headers.conf` | feat |
| Use-case pages | Data-driven `UseCaseLayout` + `useCases.ts` (older content) | n/a (branched before master's versions existed) | reference only |
| Deploy | `deploy_gcp.sh` rewrite: fetches Firebase web config via API at deploy time, passes as Cloud Build substitutions (`cloudbuild.ietech-landing.yaml`), `MIN_INSTANCES=0/MAX=2`, named-Firestore-DB support (`VITE_FIREBASE_DATABASE_ID`) | not addressed | **stash** |

**Verdict:** the stash is ~90% superseded. **Salvage 3 things**, then it can be dropped:
1. `scripts/deploy_gcp.sh` rewrite + `cloudbuild.ietech-landing.yaml` (solves how `VITE_FIREBASE_*` reach the build container; cuts idle cost).
2. `src/firebase/config.ts` named-database support (`getFirestore(app, databaseId)`) — only if a non-default Firestore DB is actually in use.
3. Optionally `useCases.ts`/`UseCaseLayout` as the design reference for de-duplicating the two 500-line use-case pages.

The stash is preserved as `stash@{0}` ("local WIP (SEO/router/use-cases work)…"). Extract single files with `git show 'stash@{0}^3:<path>'` (untracked) or `git diff stash@{0}^ stash@{0} -- <path>` (tracked). Do not `git stash pop` wholesale — it conflicts with current master.
